## 8 算法流程与关键实现

### 8.1 流水线

```
输入视频帧 I_t
  → ① GMM 逐像素背景建模（主实验用 OpenCV MOG2）   输出原始前景掩码 M_t
  → ② 二维傅里叶变换                              F = fft2(M_t)
  → ③ 构造高斯低通并频域逐点相乘（卷积定理）          H(u,v)=exp(-D²/2D0²)，F_f = F ⊙ H
  → ④ 逆傅里叶变换 → 取模 → 阈值二值化 τ=0.5        M'_t = (|ifft2(F_f)| > 0.5)
  → ⑤ 更新 GMM 参数，读取下一帧
输出净化掩码序列 {M'_t}
```

### 8.2 五个关键实现要点

| # | 要点 | 具体做法 | 为什么 |
| --- | --- | --- | --- |
| 1 | **未移位频谱约定** | 滤波器用 `np.fft.fftfreq(w, 1.0/w)` / `fftfreq(h, 1.0/h)` 按"周期性"频率坐标构造，直流落在索引 `[0,0]`，与未作 `fftshift` 的 `np.fft.fft2` 频谱严格对齐；仅在可视化时才 `fftshift` | 若滤波器原点设在数组中心而频谱未中心化，二者原点错位，会把远离直流的窄带误当作低频，导致输出幅值严重衰减 |
| 2 | **纯后置模块** | `fft_gaussian_denoise()` 的输入输出都是二值掩码，完全不触碰 GMM 的时序更新逻辑 | 可无差别串接到任意像素级背景建模算法之后（论文"移植性强"结论的直接依据） |
| 3 | **用高斯低通而非理想低通** | $H=\exp[-D^{2}/(2D_0^{2})]$，无阶跃间断 | 理想低通硬截断等价于 sinc 核卷积，旁瓣正负交替，会在阶跃边缘两侧产生过冲（吉布斯振铃）；二值掩码的轮廓本身就是阶跃结构 |
| 4 | **阈值 0.5 有几何含义** | 逆变换幅值＝"以该像素为中心的局部邻域被前景填充的比例"，前景内部趋近 1、背景趋近 0，故取 0.5 即要求邻域内至少半数被前景占据 | 有明确物理解释，且是本文**唯一**阈值；孤立单点噪点占比极低，被稀释后必然低于 0.5 |
| 5 | **手写 GMM 仅作原理对照** | 主实验用 OpenCV `MOG2` 保证工程可信度；另手写极简 `SimpleGMM`（K 个分量、均值/方差/权重在线更新，匹配判据 $|I-\mu|<2.5\sigma$）跑前 70 帧与 MOG2 对照 | 说明"逐像素独立建模"这一缺陷的根源，同时不牺牲主实验的性能与可复现性 |

## 11 实验设计

**为什么用自建合成序列**：公开监控数据集通常仅提供视频级或少量关键帧级标注，难以逐帧计算误检率、漏检率与 IoU；而合成序列中运动目标由**纯矩形**绘制、不含纹理，可生成与图像内容严格一致、逐像素对齐的真值掩码，使指标计算具备客观基准。合成方式还可精确控制动态干扰的类型与强度（水面波纹、树叶抖动、人行道阴影、第 120 帧起的全局光照渐变），便于定向验证方法的有效边界；随机种子固定，结果完全可复现。序列仅 240×160、200 帧，完全离线，不需要联网下载数据集。

**对照设置**：

- ① **基础算法**：OpenCV `MOG2`（`history=300`、`varThreshold=16`、`detectShadows=False`）直接输出原始掩码
- ② **本文方法**：同一原始掩码经二维傅里叶高斯低通（$D_0=0.08$、$\tau=0.5$）净化

两组共用同一份输入帧序列与同一份原始掩码，唯一差异是后处理模块，因此差异可归因于频域净化本身。

**评价指标**：

| 指标 | 定义 | 期望方向 |
| --- | --- | --- |
| 误检率 FPR | FP/(FP+TN)，背景被误判为前景的比例 | 越低越好 |
| 漏检率 FNR | FN/(FN+TP)，前景被漏判的比例 | 越低越好 |
| 轮廓完整度 IoU | TP/(TP+FP+FN)，与真值的重叠程度 | 越高越好 |
| 椒盐噪点像素占比 | 面积 < 4 像素的孤立连通块像素占比 | 越低越好 |
| 孤立连通块个数 | 面积 < 4 像素的连通块数量（逐帧统计后取均值） | 越低越好 |
| 远场时间抖动 | 无目标区（第 5~40 行）相邻帧掩码翻转像素占比 | 越低越好 |
| 单帧耗时 | GMM、频域滤波、空域高斯对照各重复 3 次取均值 | — |

统计时**跳过前 50 帧**冷启动阶段（`WARMUP=50`），并另设分段统计（常规段 50~119 帧 / 光照渐变段 120~199 帧）来定位方法的有效边界。

## 13 已知限制与注意事项

### 13.1 路径全部硬编码，不可直接迁移 ⚠️

`build_nb.py`、`make_figures.py` 以及 `_tools\` 下所有脚本都使用**绝对路径** `D:\workspace\Jupyter_WorkSpace\DIP\...`，且未使用 `__file__`。后果：

- 把 `0202` 目录拷到别处运行脚本，产物会**写回原路径**，而不是新位置；
- 把整棵 `DIP` 拷到别处，`exec_nb.py` / `verify.py` / `check_md.py` / `build_docx_md.py` 仍指向原仓库；
- 原路径不存在时，因为代码含 `mkdir(parents=True, exist_ok=True)`，脚本会**在原地重建整条目录树**并写入，而不会报错提醒。

> 这是本仓库的既有约定（各章一致），非本章特有。如需迁移，应改为基于 `Path(__file__).resolve().parent` 的相对路径方案。

### 13.2 重跑 `build_nb.py` 会清空 Notebook 输出 ⚠️

`build_nb.py` 写出的 cell 是 `execution_count: None, outputs: []`。**单独重跑它会让 Notebook 失去全部输出和插图**，`verify.py` 的"全部代码单元已执行""图已内嵌"两项会立即变为不通过。必须在之后接跑 `exec_nb.py`。

### 13.3 `exec_nb.py` 应传 Notebook 完整路径

传章节号 `0202` 时，它按 `DIP_ROOT / "0202"` 解析；但若当前工作目录下恰好存在同名 `0202` 文件夹，会优先命中该文件夹并在其中找不到 `.ipynb` 而报错。建议始终传完整路径。

### 13.4 论文表6 的耗时数字与当前 Notebook 输出不一致 ⚠️

论文 3.7 节表6（及摘要、结论中的 1.10 ms/帧、638 帧/s）与 `data\key_numbers.json`、Notebook 单元 `6.1` 的当前实测值不是同一次测量的结果：

| 传统 GMM 单帧耗时 / ms | 0.475 | 0.479 |
| 频域滤波后处理 / ms | 1.097 | 1.121 |
| 本文方法总计 / ms | 1.567 | 1.600 |
| 空域高斯对照 / ms | 1.069 | 1.305 |
| 本文方法等效帧率 / FPS | 638 | 625 |

耗时为机器相关量，重跑会变；精度类指标（FPR、FNR、IoU、椒盐统计）在两种口径下完全一致，不受影响。若要严格对齐，应以当前 `key_numbers.json` 为准重跑论文表6。
